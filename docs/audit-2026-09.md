# September 2026 audit

## Fixed in this pass

* Downloads use exclusive file creation, so a path occupied after filename selection is not overwritten. Successful completion is published after closing the file; idle HTTP connections are closed.
* Console visibility changes apply only when Womprat is the sole attached process. An inherited command-shell console is left alone.
* WebView2 initialization interprets HRESULTs as signed 32-bit values. Synchronous controller creation and failed/null WebView retrieval terminate initialization rather than hanging or dereferencing nil; message-loop errors terminate the loop.
* The loopback HTTP listener rejects foreign Host headers before serving token-bearing HTML or APIs, blocking the DNS-rebinding path. Open the printed numeric loopback URL, not a hostname alias.
* Config and credential writes stage a private temporary file, sync and close it, then replace the destination. Failed writes do not first truncate the previous encrypted file. A separate save mutex serializes config snapshot/save/commit transactions across settings, tab persistence, and host-key pinning. Directory metadata crash durability is not guaranteed on every filesystem.
* Hidden RDP tabs cancel pending resize requests and do not request a 1x1 desktop. Closing a tab disposes its observer and pointer cache; delayed codec loading cannot start a viewer on a removed panel.
* WebView2 rejects failed/non-string web-message reads and logs script/resource callback errors instead of terminating the process.
* Debug logging closes the previous file handle when reconfigured or disabled.
* Eleven COM AddRef wrappers now supply the receiver pointer. Resource-request wrappers inspect HRESULT rather than Win32 last-error; failed navigation-result getters no longer report success.
* RDP text WebSocket messages reach the message parser. Socket setup preserves per-tab viewport dimensions, colour depth, NLA and audio options rather than overwriting them with window geometry/global controls.

* Native NewWindowRequested events suppress default popup creation and route validated HTTP(S) targets to Womprat tabs, including requests missed by JavaScript interception.
* Native ProcessFailed events provide explicit reload/reopen/restart guidance instead of silently leaving a blank tab. No automatic crash-reload loop is introduced.
* Failed permission-kind reads are denied, even when a global grant exists.

## Checks run

`make verify` passed: frontend bundle checks, host Go tests, Windows ARM64 vet, and ARM64/AMD64 application builds. `go test -race ./...` passed. The Linux Playwright shell run passed 11 checks, including downloaded file bytes and tab reorder/close. `bun test tests/ux/rdp-resize.test.mjs` passed eight behavioural/contract tests against the shipped frontend. These tests are now included in `make verify` through `make frontend-test`.

The nested WebView2 module builds for Windows AMD64 and its new initialization tests cross-compile for Windows ARM64. Eight AMD64 callback-level tests also passed under Wine, including HRESULT failures, AddRef receiver forwarding, and invalid scripts. This does not validate the native WebView2 runtime. The nested RDP Display Control protocol tests passed; its public package currently has no tests.

## Remaining review and validation

This is not a claim that all browser functionality is verified. Remaining work includes real-WebView2 validation of the native popup and process-failure handlers, native download events, and authenticated downloads. Popup redirection creates a fresh URL navigation; it does not preserve POST bodies or opener-window semantics. The managed downloader does not share WebView2 cookies.

Live Windows console behaviour and full WebView2 failure injection require Windows execution. The installed XRDP could not read its TLS key, so validation used a separate loopback listener on port 3398, temporary TLS files, and a private mount namespace for PID files, sharing the existing sesman socket directory. Real RDP then passed 3/3 checks: non-uniform framebuffer pixels at 1280x636, full resized viewport coverage, mapped centre coordinates, unchanged WebSocket, and no browser errors. A separate Xvfb/x11vnc target passed 3/3 real VNC checks at 1024x768. These test processes do not modify the installed service configuration.

The RDP object-fit rule now uses fill, matching independent X/Y pointer scaling rather than introducing an internal letterbox. The pixel checks do not yet verify the rendered response to a remote click. Native certificate policy, permissions, uploads, printing, and clipboard behaviour still need dedicated Windows end-to-end validation before a comprehensive audit can be considered complete.
