# September 2026 audit

## Fixed in this pass

* Downloads use exclusive file creation, so a path occupied after filename selection is not overwritten. Successful completion is published after closing the file; idle HTTP connections are closed.
* Console visibility changes apply only when Womprat is the sole attached process. An inherited command-shell console is left alone.
* WebView2 initialization interprets HRESULTs as signed 32-bit values. Synchronous controller creation and failed/null WebView retrieval terminate initialization rather than hanging or dereferencing nil; message-loop errors terminate the loop.
* The loopback HTTP listener rejects foreign Host headers before serving token-bearing HTML or APIs, blocking the DNS-rebinding path. Open the printed numeric loopback URL, not a hostname alias.
* Config and credential writes stage a private temporary file, sync and close it, then replace the destination. Failed writes do not first truncate the previous encrypted file. A separate save mutex serializes config snapshot/save/commit transactions across settings, tab persistence, and host-key pinning. Directory metadata crash durability is not guaranteed on every filesystem.
* Hidden RDP tabs cancel pending resize requests and do not request a 1x1 desktop. Closing a tab disposes its observer and pointer cache; delayed codec loading cannot start a viewer on a removed panel.
* WebView2 rejects failed/non-string web-message reads and logs script/resource callback errors instead of terminating the process.
* Debug logging closes the previous file handle when reconfigured or disabled.

## Checks run

`make verify` passed: frontend bundle checks, host Go tests, Windows ARM64 vet, and ARM64/AMD64 application builds. `go test -race ./...` passed. The Linux Playwright shell run passed 11 checks, including downloaded file bytes and tab reorder/close. `bun test tests/ux/rdp-resize.test.mjs` passed five behavioural tests against the shipped resize method.

The nested WebView2 module builds for Windows AMD64 and its new initialization tests cross-compile for Windows ARM64. These tests were not executed on Windows. The nested RDP Display Control protocol tests passed; its public package currently has no tests.

## Remaining review and validation

This is not a claim that all browser functionality is verified. Remaining work includes native popup/download events and authenticated downloads, and native renderer-process recovery. The managed downloader does not share WebView2 cookies.

Live Windows console behaviour and COM failure injection require Windows execution. Real VNC/RDP pixel and remote-input tests were not rerun in this pass; the shell run uses a VNC stub and only creates an RDP panel. Native certificate policy, permissions, uploads, printing, and clipboard behaviour need dedicated end-to-end validation before a comprehensive audit can be considered complete.
