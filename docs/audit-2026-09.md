# Security and validation notes

Womprat isolates application traffic from the host network and protects its local API and stored state. The following controls and limits apply to v0.4.0.

## Local access and storage

- HTTP and SOCKS listeners bind to loopback. The HTTP server rejects foreign `Host` headers before serving token-bearing content; API requests require a per-process session token.
- Windows configuration and credential files use user-scoped DPAPI. Master-password mode adds an application access gate; it does not replace DPAPI encryption.
- Configuration and credential writes use a private temporary file, flush and close it, then replace the destination. Failed writes leave the previous file intact. A save mutex serialises config transactions. Directory metadata crash durability depends on the filesystem.
- Recent-item dismissals are stored separately from open tabs. Removing a card does not close a session or remove it from session restore.

## Network and browser controls

- Application TCP connections and supported upstream DNS queries use the embedded Tailscale stack. Unknown or unroutable destinations fail closed without host-network fallback. The direct-dial bypass requires both a debug build and `WOMPRAT_DIRECT=1`.
- SSH uses trust on first use and rejects a changed pinned host key.
- Managed downloads validate URLs and filenames, create destination files exclusively, and remove partial files on failure. Same-origin browser downloads can inherit WebView2 cookies through expiring, one-use tickets. Cross-origin and direct-API downloads do not inherit them.
- Popup requests are redirected to validated HTTP(S) tabs. A new navigation does not retain a popup POST body or opener relationship.
- WebView2 callbacks check HRESULT and returned values. Unreadable permission kinds are denied. Browser process failures are shown in the affected tab.
- Console visibility changes apply only to a console owned solely by Womprat. Debug logging closes its file when disabled.
- Closing a remote-display tab cancels its pending resize and asynchronous initialisation work. VNC releases held keys on blur, reconnect and disposal.

## Test coverage

`make verify` runs frontend bundle and behavioural checks, Go tests, Windows ARM64 vet, and ARM64/AMD64 compile checks. Race-enabled Go tests exercise concurrent state changes and failure paths. Browser tests cover shell interactions, form geometry, copying diagnostic reports, Recent removal, downloads and protocol bridges.

The release workflow runs WebView2 COM regression tests on Windows before building and publishing both Windows binaries. COM tests exercise callback contracts; they do not cover every native WebView2 interaction. Linux browser tests use Chromium and do not instantiate the Windows child-window host. See [the test guide](../tests/ux/README.md) for commands and coverage boundaries.

Tailnet DNS and application connectivity have also been exercised on Windows with a split-DNS bridge and an exit node. Automated local DNS fixtures test parsing, policy selection and transport rejection; they do not establish connectivity to another tailnet's services.

## Known limits

- RDP server certificate verification is disabled. TLS can encrypt the connection without authenticating the server certificate. Use trusted targets and verify their identity independently.
- DNS upstreams are limited to IP-addressed TCP DNS and IP-addressed exit-node HTTP DNS. Alternate-server retries and HTTPS/hostname upstreams are not implemented.
- Remote framebuffer tests check pixel output and resize geometry; they do not verify every remote input action.
- Native uploads, printing, failure injection and clipboard edge cases need broader Windows end-to-end coverage.
- Womprat does not provide a machine-wide VPN or USB-contained state. Its encrypted Windows state is tied to the user account.
