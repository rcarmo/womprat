Release workflow [42009048716](https://github.com/rcarmo/womprat/actions/runs/42009048716) passed every job: native Windows amd64/arm64 COM tests, Windows builds, Fedora/Atomic AppImage acceptance and Linux publication. The previous v0.4.5 tag and release were unchanged.

## Public assets

All three binaries were downloaded from the public release, checked against the published Windows/Linux checksum files and inspected with `go version -m`. Each embeds Go 1.27.3, version 0.4.6 and commit f06e507. Windows targets are ARM64 and AMD64 with GUI release flags; Linux is amd64-v1 with webkitgui only, without test/profile tags or direct-dial override. Extracted AppRun matches the symlink-aware launcher source. The release is neither a draft nor a prerelease and is the latest GitHub release.

Fedora tests exercise native viewport zoom with content/address-bar focus, shifted/keypad handling, terminal font zoom/reset, normal-user sandboxing, directory/symlinked /opt layouts, release network canaries and process-restart/unlock behaviour. ## Profile review and disposal

Windows amd64: 260ms sampled CPU over 304ms, 5470KiB allocated / 41563 objects; ARM64: 220ms over 218ms, 5358KiB / 39818 objects. Allocation-profiler/stack-walking overhead dominates the small COM test workload; native zoom ABI tests passed.

Host Go contracts: 340ms CPU samples over 6.61s, 14711KiB / 37430 objects; PBKDF2 about 44.1% cumulative CPU retained. Fedora native Go: 890ms over 4.09s, 8669KiB / 34474 objects; cgocall 46.1% flat. GTK-linked contracts: 440ms over 5.52s, 15177KiB / 38653 objects. Native allocations are principally profiler initialisation, bounded configuration snapshots and one-time fixture PNG encoding, consistent with preceding equivalent workloads. No new material application outlier or performance-gain claim.

Native perf: 317 samples, zero lost, loader relocation about 30.6% cumulative with renderer stacks. GTK host heaptrack: 258544 allocation calls, 26006 temporary, 4.42MB peak heap, 225.43MB RSS including profiler overhead. These short startup workloads do not establish steady-state performance or renderer allocation history; sandboxed helpers may scrub heaptrack preload. CPU, alloc_space and alloc_objects reports were reviewed, then raw profiles, matching binaries, extraction tree, verification copies and disposable logs were removed. All four remote transient profile artifacts were deleted after review. Intentional published binaries/checksums are retained separately in build/dist; public assets remain on GitHub.
